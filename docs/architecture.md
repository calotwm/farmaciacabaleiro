# Farmacia Cabaleiro — Architecture

Inventory management for a single pharmacy: product catalog, lot-based stock with expiry control (FEFO),
suppliers and scheduled deliveries, goods receiving, notifications, reports and audit.

## 1. Style

Modular monolith, hexagonal per module. One Next.js (App Router) app plus a separate worker process
for scheduled jobs. One PostgreSQL database.

```
src/
  app/                    Next.js routes (thin: parse input, call use cases, render)
  modules/<module>/
    domain/               Pure TypeScript: entities, value objects, rules. No Prisma/Next imports.
    application/          Use cases and ports (interfaces). Orchestrates domain + ports.
    infrastructure/       Adapters: Prisma repositories, email, push, etc.
    ui/                   Container (data/actions) and presentational components.
  shared/
    domain/               Dates/timezone, money, expiry status, domain errors.
    application/          Cross-cutting application helpers (error -> user message).
    config/               Zod-validated environment.
    infrastructure/db/    Prisma client factory.
  worker/                 node-cron process (daily alert rules)
prisma/                   Schema, migrations, seed
```

Dependency rule: `domain` <- `application` <- `infrastructure` / `ui` / `app`. Domain never imports outward.
Business rules are enforced on the server; the UI is never the only guard. UI copy is neutral Spanish (es-AR);
code, identifiers, comments and docs are English.

### Planned modules

| Module | Responsibility |
| --- | --- |
| `auth` | Login, sessions, password reset, RBAC guards |

## 2. Data model overview

Defined in `prisma/schema.prisma` (snake_case tables, UUID ids generated by Postgres).

- Access: `Role`, `Permission`, `RolePermission`, `User`, `Session`, `PasswordResetToken`, `AuditLog`.
- Catalog: `Category`, `Unit`, `Product`.
- Inventory: `Lot`, `StockMovement`, `AdjustmentReason`, `StockCount`, `StockCountLine`.
- Suppliers and deliveries: `Supplier`, `SupplierProduct`, `ScheduledDelivery`, `DeliveryExpectedItem`.
- Receiving: `Receipt`, `ReceiptLine`, `ReceiptIssue`.
- Notifications: `AlertEvent`, `Notification`, `NotificationPreference`, `UserNotificationSettings`,
  `PushSubscription`, `NotificationDelivery` (outbox).
- Settings: `Setting` (key/value JSON).

## 3. Key invariants

1. **Stock lives in lots.** A product has no stock column. Physical, available and blocked stock are derived
   by summing its lots (`current_quantity`, `blocked_quantity`; available = current - blocked, excluding
   expired/blocked/quarantine lots). CHECK constraints keep quantities non-negative and
   `blocked_quantity <= current_quantity`.
2. **Movements are append-only.** `stock_movements` rejects UPDATE, DELETE and TRUNCATE through a Postgres
   trigger. Corrections are compensating movements, never edits — even for admins.
3. **No negative stock, no override.** Exits are validated against the lot inside the same transaction.
4. **Expired lots** only allow write-off or return with a reason; they are never dispensed.
5. **Idempotency.** Receipt confirmation is keyed by `Receipt.idempotencyKey` (unique); `AlertEvent` is unique on
   (rule, entity type, entity id, threshold key, event date), so a repeated worker run creates nothing new.
6. **Notification failures never roll back business transactions.** External channels go through the
   `NotificationDelivery` outbox processed by the worker.
7. **Authorization on the server.** Every server action and route handler calls `requireUser()` /
   `requirePermission(key)`; middleware only does a cheap cookie-presence redirect.

## 4. Dates and timezone rules

Implemented in `src/shared/domain/dates.ts`; tested with the server TZ forced to UTC, Asia/Tokyo and
America/Los_Angeles.

- The pharmacy timezone is `America/Argentina/Buenos_Aires` (UTC-3, no DST). It is a constant default now and
  will be read from the `locale.timezone` setting later.
- **Calendar dates** (lot expiry, event dates) are plain `YYYY-MM-DD` strings (`CalendarDate`) in the domain and
  `DATE` columns in Postgres. They carry no zone, so they never shift. Prisma returns DATE as a `Date` at
  UTC midnight; use `fromDbDate` / `toDbDate` at the boundary.
- **Instants** (movements, receipts, sessions) are `timestamptz` and are rendered in AR time with
  `formatDateTime`.
- **"Today"** is `todayInTz(now)`: the calendar date in the pharmacy timezone, never the server's.
- A lot **expires at the end of its stated day**: valid through the expiry date, expired from the next day.
  `MM/AAAA` input maps to the last day of that month (`expiryFromMonthYear`).
- Display format is `DD/MM/AAAA` (and `HH:mm` 24h). Money is `es-AR` / `ARS` by default (`formatMoney`).

### Expiry status

`assessExpiry(expiryDate, today, { thresholds, criticalDays })` in `src/shared/domain/expiry-status.ts`:

| Status | Rule |
| --- | --- |
| `EXPIRED` | today is after the expiry date |
| `CRITICAL` | days left <= 30 (`criticalDays`, includes the expiry day itself) |
| `WARNING` | days left <= largest threshold (default 180) |
| `NORMAL` | otherwise |

Default thresholds are `[180, 90, 60, 30, 7]`. `crossedThreshold` is the smallest threshold greater than or equal
to the days left (the alert bucket the lot is in), or `null`.

## 5. Configuration

`src/shared/config/env.ts` validates the server environment with Zod and fails fast, listing every problem.

| Variable | Required | Notes |
| --- | --- | --- |
| `DATABASE_URL` | yes | PostgreSQL connection string |
| `DATABASE_SSL_REJECT_UNAUTHORIZED` | no | `false` only for dev proxies with self-signed certs; never in production |
| `APP_URL` | no | Defaults to `http://localhost:3000`; used in emailed links |
| `SESSION_SECRET` | no | Reserved; min 32 chars when set |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | no | All three together enable Web Push |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | no | All together enable email; free SMTP (e.g. Gmail app password) is enough |

## 6. Errors

`src/shared/domain/errors.ts` defines `DomainError` and subclasses (`NotFoundError`, `ForbiddenError`,
`UnauthenticatedError`, `ValidationError`, `ConflictError`, `RateLimitError`). They are mapped to Spanish messages
at the edge by `toUserMessage` (`src/shared/application/user-message.ts`); unknown errors never leak internals.

## 7. Accepted assumptions

1. A lot expires at the end of the stated day; `MM/AAAA` means the last day of the month.
2. Expired lots only allow write-off/return with a reason.
3. No negative stock and no override.
4. Corrections use compensating movements, even for admins.
5. Single tenant, no POS integration.
6. Zero budget: anything paid is replaced by a free alternative or skipped and documented.

## 8. Decisions (ADR-style)

| # | Decision | Why |
| --- | --- | --- |
| 1 | Modular monolith, hexagonal modules | One deployable, clear boundaries, testable domain |
| 2 | Own auth with DB sessions and argon2id | No paid IdP; revocable sessions; hashes only in DB |
| 3 | Stock derived from lots | Single source of truth, FEFO and expiry per lot |
| 4 | Append-only movements enforced in Postgres | Audit integrity independent of app bugs |
| 5 | Expiry as DATE, instants as timestamptz | No timezone drift in expiry logic |
| 6 | Calendar dates as strings in the domain | Zone-free, trivially comparable, server-TZ independent |
| 7 | Separate worker process (node-cron) | Daily jobs without coupling to web requests |
| 8 | Outbox for push/email | External failures cannot roll back business transactions |
| 9 | Prisma 7 with the `pg` adapter | Current Prisma architecture; one driver for app and tests |
| 10 | Railway proxy cert is self-signed | Dev-only `DATABASE_SSL_REJECT_UNAUTHORIZED=false`; production uses private network or verified TLS |
